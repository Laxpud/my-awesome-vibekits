# Agent 项目指导文件维护

## 目标

让 agent 在任务开始时以尽量小的上下文找到正确文档和代码入口，并看见必须立即生效的工作流触发器与高风险边界。项目指导文件是薄路由，不是 README、规划、architecture 或维护手册的副本。

本 Skill 只修改仓库范围内的指导文件。用户全局规则、插件配置和外部系统权限需要另行授权与对应工作流。

## 共同底线

1. 编辑前读取仓库证据和适用项目指导。
2. 尊重既有权威位置、清晰约定和用户拥有的改动。
3. 不编造项目目的、架构、命令结果或完成状态。
4. 同一主题保留一个权威来源，其他位置使用短路由或链接。
5. 按“仓库证据 → 插件默认值 → 高风险澄清”决策；用户要求“按默认值”也不授权不可逆操作。
6. 回读改动，检查链接和 diff，并报告假设、验证及未执行门禁。

## Reference 路由

创建、审查或重构任何项目指导文件时，读取 [`references/project-guidance.md`](references/project-guidance.md)。该 reference 包含内容分类、目录作用域、继承去重和内联规则门槛。

## 维护流程

1. **发现实际 harness。**
   - 读取现有 `AGENTS.md`、`CLAUDE.md` 和其他 agent 指导文件，以及 README、活动规划入口、具名技术文档、关键代码和配置入口。
   - 创建或依赖目录级文件前，核对对应工具当时的发现、作用域、聚合和优先级规则；不能把一个平台的语义推广到其他格式。
   - 只有用户要求、对应工具正在使用，或确有有价值的路由、工作流触发器或高风险边界时才创建文件。

2. **分类现有内容。**
   - 保留入口路由、必要工作流触发器和少量高风险边界。
   - 项目介绍、公共能力和最短路径路由到 README。
   - Roadmap、milestone、task、完成与归档规则路由到唯一活动规划入口。
   - Architecture、数据契约、配置、测试和故障排查路由到具名技术文档。
   - 面向人类的贡献流程和维护手册不由本 Skill 接管。

3. **写薄入口。**
   - 优先使用“修改某类内容前，读取某个最小权威文件”的短路由。
   - 只有具体改动会触发必要配套步骤时才保留工作流触发器。
   - 只有遗漏可能造成破坏性操作、外部副作用、安全问题或仓库级严重回归时才保留高风险边界。
   - 规划集成只保留：开始相关工作前读取已声明活动入口，交付前按其契约同步状态。

4. **按作用域放置。**
   - 根文件只保留整个仓库有效的内容。
   - 局部规则放到覆盖目标的最深有效目录；下级文件只补充、收窄或明确覆盖，不重复上级已经生效的内容。
   - 没有目录专属规则时不创建下级指导文件。

5. **协调多平台文件。**
   - 共同事实链接相同权威来源，只重复必须在上下文中立即可见的短路由和高风险边界。
   - 平台专属命令、发现规则和配置只放对应文件。
   - 同一改动影响共享路由时，同轮检查全部受维护指导文件，但不强迫不同平台拥有相同结构。

6. **验证。**
   - 检查每个 pointer 同时说明目标是什么和何时读取，且指向真实、范围最小的文件。
   - 检查详细主题只有一个权威来源，根与下级文件没有重复生效规则。
   - 回读全部受维护文件并检查链接、目录作用域、平台差异和 Git diff。

## 示例

正例：

```text
重构 AGENTS.md 和 CLAUDE.md，把架构、规划和测试细节移回权威文档，并整理目录级规则。
```

预期：验证两种工具的文件语义，保留薄路由、触发器和高风险边界，把局部规则下沉且避免继承重复。

近邻反例：

```text
请重写 CONTRIBUTING.md，解释给人类贡献者的评审与发布流程。
```

这是面向人类的协作文档，当前六个 `project-docs` Skill 均不负责。
