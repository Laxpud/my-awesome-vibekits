# Agent 项目指导文件

## 职责

项目指导文件是 agent 工作的快速路由层。它帮助当前任务找到：

- 最小权威文档和代码入口；
- 具体改动触发的配套工作流；
- 遗漏后可能造成破坏性操作、外部副作用、安全问题或仓库级严重回归的边界。

它不是 README、规划文档、architecture、测试手册或人类贡献指南的副本。

## 所有权映射

| 内容 | 权威位置 | 指导文件处理 |
| --- | --- | --- |
| 项目目的、公共能力、环境和最短路径 | 根 README | 需要公共背景时链接 |
| Roadmap、milestone、task、状态和证据 | 已声明活动规划入口 | 保留工作前读取、交付前同步的短路由 |
| Architecture、数据契约、配置、测试和稳定技术细节 | `docs/` 下具名文档 | 按改动类型链接最小权威文件 |
| Agent 入口路由、工作流触发器和高风险边界 | 对应项目指导文件 | 简短、可执行地内联 |
| 面向人类的贡献和维护流程 | `CONTRIBUTING.md` 或维护手册 | 当前 Skill 不接管 |

仓库使用其他权威文件时沿用，不创建并行事实来源。

## 审查流程

1. **盘点实际 harness 与权威位置。** 读取根到目标目录间的指导文件、README、活动规划入口、相关技术文档、代码和配置入口。查阅对应工具的发现、聚合和优先级规则。
2. **逐段分类。** 标记为入口路由、工作流触发器、高风险边界或应由其他文档负责的内容。
3. **迁移详细内容。** 把项目介绍、完整规划生命周期、architecture、schema、配置、测试和故障排查移回权威文档；指导文件保留必要 pointer。
4. **围绕改动类型组织。** 优先使用“修改 `<area>` 前读取 `<authoritative-file>`”形式，并链接范围最小的文件。
5. **筛选内联规则。** 只有必要工作流触发器和高风险边界保留，低影响偏好与通用工作习惯删除。
6. **按目录作用域放置。** 局部规则下沉到最深有效目录，下级只补充或明确覆盖，不重复上级。
7. **协调平台文件。** 共享事实链接同一权威来源，平台专属发现、命令和配置保留在对应文件。

## Context pointer 检查

每个 pointer 同时回答：

1. 目标材料是什么；
2. 哪类任务或改动需要读取它。

“更多信息见 docs”缺少触发分支；“修改数据格式前读取 `docs/data-contract.md`”同时具备目标和条件。优先链接具名文件，不链接宽泛目录。

## 内联规则门槛

保留一条非路由规则前，确认：

- 有具体改动或操作会触发它；
- 规则有仓库证据或用户明确决定；
- 只提供链接不足以让必要行为在关键时刻可见；
- 措辞简短、可执行，且适用范围准确。

如果 agent 能从默认行为、文件名、目录或附近上下文可靠推断，删除该规则。个人偏好和“编辑前先读文件”等通用建议通常不能通过门槛。

## 目录层级

- 根文件只保留全局有效入口、触发器和高风险边界。
- 目录局部规则放在覆盖全部目标的最深有效目录。
- 下级文件继承上级时不重复解释，只补充、收窄或明确覆盖。
- 没有局部规则时不创建下级文件。
- 依赖更深文件优先级前，先确认该平台实际采用该行为。

## 验证清单

- 指导文件主要是薄路由，而不是项目手册。
- 每类详细信息只有一个权威来源。
- 活动规划集成只保留工作前读取、交付前同步的短路由。
- 根与下级作用域准确，继承内容没有重复。
- 多平台文件共享事实一致，平台专属内容没有泄漏。
- 所有 pointer 指向真实、范围最小的文件，并写明触发条件。
- 最终文件足够短，适合在每次相关任务开始时加载。
