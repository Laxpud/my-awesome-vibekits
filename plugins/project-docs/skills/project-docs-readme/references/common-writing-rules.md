# 通用文档与写作规范

七个技能共用此文件。

## 规范读取与修改范围

按技能入口的路由先读当前类型的相关规范，创建或实质重写时读模板。已读且未变化的资料不重复读取；配套资料不触发其他技能，也不要求加载全部资料。

阅读和修改限于本次范围：局部修订只处理相关内容，仅修链接不改版全文。项目缺少必要文档时按默认约定补齐最小内容；只审查时提出建议。配套资料缺失时说明影响，继续不依赖它的工作，不声称已完整遵循规范。

只核对改动涉及的规范与引用；保留适用的项目验证要求，不额外增加全库审计或逐句复审。历史原文与有效独有信息按授权范围保留。

## 写作

- 先写谁做什么、发生什么变化、还有什么未完成。使用常见词和完整句子，不把正文压成术语串。
- 标题可以简短；正文要交代对象、动作和结果。例如“完成验证闭环”改为“正常输入和单项失败场景均通过”；“实现多后端能力收敛”改为“两个后端现在使用同一份输入配置”。
- README 和使用说明面向初学用户；TODO 写可识别的交付结果；技术文档保留准确术语并解释必要概念；ADR 简短交代理由；AGENTS 可以紧凑，但条件、范围和动作必须明确。
- 每个事实和任务状态只维护一处，其他文档链接过去。没有真实内容不建空文件、空目录或空章节。
- 默认更新当前状态，不追加会话日志、交接摘要、验证报告或重复总结。执行验证不等于保存验证经过。
- 归档的 plan/spec 和旧历史不因写作规则重写。
- 用户明确要求与项目约定优先于默认模板。已授权修改直接执行；只有缺失信息实质影响结果或需要新增授权时才提问。
