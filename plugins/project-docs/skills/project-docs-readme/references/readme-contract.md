# 根 README 公共入口契约

## 最小内容

面向用户的根 README 默认回答：

1. 项目是什么，主要受众是谁；
2. 用户可以完成哪些已经存在的操作；
3. 支持环境、合理前置条件或重要限制是什么；
4. 推荐的首次成功路径是什么；
5. 哪个可观察结果表示路径已经走通；
6. 活动工作和必要技术细节在哪里。

不要求固定标题、篇幅、完成时长或通用模板。章节顺序服从项目定位；项目存在终端用户时，默认先完成用户的首次成功路径，再介绍 internals、architecture 和维护细节。纯维护者项目则把维护者视为预期用户。

## 读者与首次成功

- 从仓库证据与用户决定识别实际受众，不把“所有人”当作默认答案。
- 面向多个熟练度层级时，完整路径服务最缺乏经验的预期用户，但不教授项目边界之外的通用知识。
- 有多个平台、客户端或使用分支时，先推荐一个默认路径，再让读者按已有环境或目标选择其他路径。
- 面向新手时，只解释完成路径所需的概念、命令输入位置和占位符替换方式。
- 文件或模板类项目应在有帮助时说明先修改什么，以及哪些生成物或内部文件不应直接修改。
- 路径结束时给出可观察的成功信号；稳定、常见且会阻断首次成功的问题保留简短排查，其余链接到权威文档。

## 合理前置条件

- 只列出开始推荐路径真正需要的工具、账户、环境、输入或权限。
- 如果预期用户可能尚未安装关键工具，优先提供官方直达链接，并在合理范围内为每个受支持平台或客户端给出一个当前可验证的推荐安装命令或 GUI 步骤。
- 明确命令或操作应该发生在系统终端、Agent 输入区、IDE、浏览器还是其他界面；同时给出验证或启动步骤及其成功信号。
- 备选安装方式链接到官方说明，不在 README 中复制完整安装矩阵。
- 无法实际验证命令或 GUI 路径时，说明证据来源和未验证边界，不把推测写成事实。

## 实施门槛

定位、结构、安装或快速开始发生实质变化时，先提交只读审计，至少包含目标读者、缺失前置条件、最短已验证路径、成功结果和有序修改计划；默认等待确认后再编辑。用户已经确认过同一范围与计划，或明确要求直接实施时，可以继续执行而不重复询问。

## 证据

- 项目名称和能力来自 manifest、公开入口、源码、测试或用户明确决定。
- 安装和运行命令来自官方文档、实际 CLI、配置或已执行验证；不能运行时说明证据与限制。
- 版本、平台、依赖和状态不得根据常见做法推断。
- 删除能力说明前检查它是否仍由代码、发布物或其他受维护文档支持。

## 语言与翻译

- 沿用现有清晰语言约定；新项目默认英文根 README。
- 只有明确受众、用户要求或既有双语约定时创建翻译。
- 在文件顶部提供清晰语言切换入口。
- 正式翻译保持章节结构、公共事实、能力、命令和链接一致，允许自然本地化表达。
- 公共内容变化时同轮检查全部受维护翻译；无法同步时明确记录漂移，而不是静默遗漏。

## 链接

- 链接已声明的活动规划入口和具名技术文档或技术索引。
- 不从公共 README 链接仅供局部维护者使用的目录 README，除非仓库已有明确且有价值的公共导航约定。
- 使用能直接到达目标内容的文件和锚点，避免只链接宽泛目录。
- 移动公共链接目标时考虑外部引用稳定性，必要时保留 redirect note。

## 停止线

最缺乏经验的预期用户无需猜测即可判断项目是否适用、完成推荐路径并识别成功结果后停止。README 不是所有项目知识的汇总页。
