# 根 README 公共入口契约

## 最小内容

根 README 默认回答：

1. 项目是什么，主要受众是谁；
2. 用户可以完成哪些已经存在的操作；
3. 支持环境、前置条件或重要限制是什么；
4. 最短已验证路径是什么；
5. 活动工作和必要技术细节在哪里。

章节标题和顺序服从项目定位，不要求固定模板。详细 architecture、规划状态、维护流程、完整文件树和长篇故障排查链接到其权威位置。

## 证据

- 项目名称和能力来自 manifest、公开入口、源码、测试或用户明确决定。
- 安装和运行命令来自实际 CLI、配置或已执行验证；不能运行时说明证据与限制。
- 版本、平台、依赖和状态不得根据常见做法推断。
- 删除能力说明前检查它是否仍由代码、发布物或其他受维护文档支持。

## 语言与翻译

- 沿用现有清晰语言约定；新项目默认英文根 README。
- 只有明确受众、用户要求或既有双语约定时创建翻译。
- 在文件顶部提供清晰语言切换入口。
- 正式翻译保持章节结构、公共事实、能力、命令和链接一致，允许自然本地化表达。
- 公共内容变化时同轮检查全部受维护翻译；无法同步时明确记录漂移，而不是静默遗漏。

## 链接

- 链接已声明的活动规划入口和具名技术文档或技术索引。
- 不从公共 README 链接仅供局部维护者使用的目录 README，除非仓库已有明确且有价值的公共导航约定。
- 使用能直接到达目标内容的文件和锚点，避免只链接宽泛目录。
- 移动公共链接目标时考虑外部引用稳定性，必要时保留 redirect note。

## 停止线

新读者能在一分钟内判断项目是否适用并开始最短路径后停止。README 不是所有项目知识的汇总页。
