# Mermaid 架构图与 C4 分层

Mermaid 是默认的可 diff 文本表达格式；C4 是选择抽象层级的方法，不要求使用特定 C4 语法或绘制完整四层。

## 选择层级

- **System Context**：外部用户、系统或组织与当前系统的关系会影响理解时使用。
- **Container**：存在多个可独立运行、部署或持久化的单元时使用。C4 Container 不等于 Docker container。
- **Component**：单个运行单元内部存在稳定、重要且不直观的职责关系时使用。
- Code 层通常由源码本身表达，不作为默认 architecture 文档层级。

小型库或单进程工具不应为了完整 C4 画多个只有一个方框的层级。选择能解释真实关系的最小层级。

## 图与正文

当前态架构概览和独立子系统 architecture 文档必须至少有一张有信息量的图。图展示：

- 外部参与者和系统边界；
- 主要运行或部署单元；
- 稳定职责关系；
- 关键同步、异步或数据流向；
- 必要的信任、所有权或持久化边界。

正文说明每个边界为什么存在、主要职责与非目标、重要约束、关键流程以及可验证证据入口。不要逐句复述图，也不要让图成为唯一架构事实来源。

## Mermaid 写法

- 使用稳定、可读的节点 ID，显示标签与源码名称保持一致。
- 同一图只表达一个抽象层级或清楚标注跨层关系。
- 箭头标签说明关系或流向，不用无含义的双向线制造连接感。
- 节点和边数量开始遮蔽重点时拆图，并在正文解释各图关系。
- 仓库已有 Mermaid 约定或 renderer 时沿用；没有约定时使用广泛支持的基础语法。

## 验证

1. 对照源码、manifest、配置和部署证据检查每个节点与关系。
2. 检查 current 与 target 图有明确标签，不把未来结构画成当前事实。
3. 使用仓库已有 renderer 执行语法验证。
4. 没有 renderer 时检查 fenced block、节点声明、引用、括号和明显语法，并在最终报告中说明未完成渲染验证。
5. PNG 或 SVG 可以作为发布产物，但 Mermaid 源码保持权威并与文档同位置维护。
