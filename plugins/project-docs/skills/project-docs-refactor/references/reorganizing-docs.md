# 整理现有文档

当仓库已有分散、重复、过期、冲突或位置不当的文档时使用本 reference。

## 盘点表

对每份相关文档记录：

- 目标受众与回答的问题；
- 当前态、目标态、活动工作或历史记录；
- 相同主题的其他来源及冲突；
- 入站链接、可能的公开外链和替换路径；
- 未解决决定、用户改动及不能丢失的证据。

读取内容和附近仓库证据，不根据文件名直接推断所有权。

## 权威来源选择

1. 先采用仓库已有且清晰的所有权约定。
2. 没有约定时，按受众和问题选择：公共入口放根 README，活动承诺放已声明规划入口，稳定技术事实放具名技术文档，agent 路由放项目指导文件。
3. 重复内容一致时，选择维护路径最清晰的来源，其他位置改为短路由。
4. 重复内容冲突时，只有仓库证据足够才采用更新或更权威来源；高影响冲突先澄清。
5. 未解决冲突进入活动规划入口或具名设计文档，并注明来源与待决问题。

## 高影响澄清门槛

同时满足以下两点才暂停询问：

1. 仓库证据不足，且没有 redirect note、保留原文、分阶段迁移等安全可逆默认值；
2. 选择会改变可能公开的路径、活动工作或决策历史的权威来源、公共承诺，或删除无法证明已经迁移的内容。

只是文件较多、内部链接可以完整更新，或风险能由短 redirect note 控制时，不因“规模大”本身暂停。用户要求使用默认值时仍保留上述不可逆边界。

## 迁移

1. 移动前检查 Git 状态，识别用户拥有和无关改动。
2. 尽量使用保留历史的移动，并根据目标位置改写阶段性或过期措辞。
3. 更新 README、规划入口、技术索引、项目指导文件和相关局部导航。
4. 内部引用可以完整搜索和更新时直接迁移。
5. 旧路径可能被公开文档、发布物或外部用户引用时，保留简短 redirect note：说明新位置、迁移原因和生效状态，不继续维护重复正文。
6. 不因文件很长而归档；只有内容已成为历史或被取代时才归档。
7. 活动工作和未决问题必须先迁出，不能通过移动或删除隐藏。

## 索引与链接

- 保留仓库已有且清晰的索引命名。新项目需要技术索引时默认 `docs/index.md`，不因偏好重命名有效的 `docs/README.md`。
- 面向用户的 README 链接具名入口或技术索引，不直接承担目录地图。
- 目录 README 从所属目录、包文档或技术索引发现；只有维护者导航确实需要时才增加入口。
- 移动后搜索旧路径、相对链接、锚点、图片、脚本和配置中的文档引用。

## 验证

- 回读全部修改文档，并检查每个主题只有一个权威来源。
- 搜索旧文件名、断链、重复定义、过期阶段词和已删除草稿引用。
- 确认 current、target、active 和 archived 内容没有混淆。
- 检查活动工作与未解决决定仍可从声明入口发现。
- 检查 Git diff 只包含计划内的结构、链接和必要改写。
