# 整理与迁移

## 范围

从用户要解决的问题和相关入口开始，不要求每次通读全仓库。局部修订只追相关引用；用户要求全库整理时才清点全体文档。

默认轻量迁移：活动任务和未来安排采用新约定，旧历史原样保留并修复受影响链接。用户显式要求时可统一历史格式；范围未定且影响结果时给出“只整理活动内容（推荐）/ 同时整理历史”的选择。已经授权的选择不反复请示，不触碰范围外项目。

## 内容去向

| 内容 | 默认维护位置 |
| --- | --- |
| 用户首次使用 | README 与正式翻译 |
| 日常任务、选项、使用问题 | 按需建立的 `docs/usage.md` |
| 当前任务 | TODO |
| 未来里程碑、未承诺候选 | roadmap 的后续里程碑与 Backlog |
| 代码结构、运行机理、开发依赖 | `docs/tech/`，小项目可单页 |
| 重要决定 | `docs/adr/` |
| 必要测量和复现材料 | 已有持久来源或 `docs/evidence/` |
| 完成的原清单及 plan/spec | `docs/archive/` |
| AI 路由与边界 | AGENTS；CLAUDE 相对软链 |

这是新建或明确迁移的默认位置，不为名称偏好搬走已清晰的文档。没有内容不建目录；不默认新增独立 backlog、current-plan、decisions、验收报告或交接文件。

## 移动和去重

选定一个事实来源，其他位置保留必要导航。移动时机械修正 Markdown 行内/引用式链接、HTML 链接、附件和入口；历史 plan/spec 不润色。删除重复副本前确认其独有有效信息已有去处，不能以整理为由删除真实原始证据或未完成状态。

明确区别错误事实、旧历史和未实施方案：修正当前错误，保留历史语境，目标方案不能冒充当前实现。整理结果说明入口和必要限制即可，不再额外创建迁移日志。
