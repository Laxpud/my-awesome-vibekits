# 目录 README

目录 README 是稳定局部职责的维护者地图，不是公共项目入口、生成文件清单或根 README 的副本。

## 创建门槛

只有目录具有以下一种或多种真实特征时才创建：

- 稳定但仅凭目录名无法理解的职责或非目标；
- 多个子区域、包或应用需要关系说明；
- 公共入口、扩展点或数据流不直观；
- 生成文件、迁移顺序或局部修改风险需要立即可见。

空目录、职责显然或频繁重排的目录不创建 README。没有目录专属信息时依赖文件名、模块说明和具名技术文档。

## 应包含

- 目录职责与非目标；
- 主要子区域及其关系；
- 公共入口或扩展点；
- 能防止错误的局部约定、生成边界或迁移风险；
- 细节已有权威位置时使用链接。

每项陈述都应由目录结构、manifest、入口、公共接口、现有文档或生成产物支撑。

## 应避免

- 默认逐文件列举；文件列表会在重命名和拆分后快速漂移。
- 复制长篇 architecture、教程、测试或故障排查；这些内容放具名技术文档。
- 把目录 README 当成根 README 或技术索引。
- 为了形式统一在所有目录创建相同模板。

## 更新或删除

- 修改前读取附近 manifest、入口、包文件、技术文档和入站链接。
- 保留仍然有效的局部约束和迁移警告，用稳定职责替换过期文件清单。
- 目录已移动、职责消失或内容全部由其他权威文档承担时，可以删除或合并；同时更新链接并迁移未解决问题。
- 所有权冲突且证据不足时，在改写前应用主 Skill 的澄清门槛。
