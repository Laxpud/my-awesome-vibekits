# 规划文档的职责

## 默认位置

| 位置 | 唯一负责的内容 |
| --- | --- |
| `TODO.md` | 当前里程碑目标、完成条件、任务与必要方案链接；下一个里程碑只有名称和 roadmap 链接 |
| `docs/roadmap.md` | 已完成里程碑链接、当前入口、未来里程碑和 Backlog |
| `docs/plans/`、`docs/specs/` | 需要长期引用的未完成 plan/spec |
| `docs/archive/` | 已结束的 milestone、plan、spec 原文 |
| `docs/evidence/` | 用户要求或后续判断、测量、复现确实依赖的材料 |

采用[具体模板](../../assets/project-docs-planning/planning-templates.md)；无内容的可选字段省略，已有清楚路径可保留。不默认增加独立 backlog、current-plan、STATUS 或 HANDOFF 文件。

## 当前与未来

任务按可交付或验证的结果拆分，不按每次编辑、函数或操作拆分。简要方案可放在所属条目下，详细方案链接；共同方案放在里程碑层，局部方案放在任务层。

默认完成只勾选。确有后续价值时最多附一条短验证句，说明对象与结论，必要材料用链接；不记录命令清单、日志、哈希、长路径、逐项结果或修复过程。必要验证没完成不能勾选，不得删弱完成条件制造完成。

近期里程碑用与 TODO 相同的目标、完成条件、任务和可选方案格式，启用时直接移动。远期只有预期结果和必要依赖，不强求日期或任务细分。Backlog 记录尚未承诺的候选价值，按需保留初步思路、待决问题和方案链接；已讨论出方案不等于授权实施。

当前详情只在 TODO，未来详情只在 roadmap，已完成详情只在 archive。Roadmap 的已完成列表每项仅名称和链接，最新在前，多时按年份分组；不以混有 plan/spec 的归档目录替代这些入口。

## 更新节点

每个里程碑保留“核对并同步本里程碑影响的项目文档”条目。复杂阶段可预设中途节点；发布时检查覆盖情况。只更新受影响事实，没有变化无需改正文。不能每完成一个代码任务就重写 architecture；失效且会阻碍当前使用的说明及时修复。

暂停、取消、共享方案和原文归档按[生命周期](lifecycle.md)处理。
