# README 约定

README 帮助初学用户判断是否适用、准备使用环境并首次成功。采用[模板](../../assets/project-docs-readme/readme-template.md)的章节顺序；无内容的可选章节省略，不强求操作形式一致。

## 开头与徽章

项目名称、可选现有图标、居中的 HTML 徽章行、一句话用途；有现成且有帮助的截图可以展示，不强制生成或寻找资源。

Shields.io 徽章统一 `style=for-the-badge`，有真实合适 logo 时带 logo。HTML 属性中的查询参数用 `&amp;`。默认语言入口在最前，其次真实许可证；中文页提供英文返回入口。缺许可证时询问，不自行选许可证或造链接。其余 platform、release、运行时版本、安装入口等只放有用且真实的项目事实，不能把测试环境当最低要求或计划支持当已支持。

徽章只在顶部，不在结尾重复。已有许可证徽章和有效链接时省略许可证章节，额外授权或署名要求确实需要时才补说明。

## 读者与内容

沿用项目语言；新项目默认英文根 README 与 `docs/README.cn.md`。创建或实质重写时默认补齐中文入口的正式译文；用户明确单语则遵从，小改不扩张为全篇翻译任务。正式翻译章节结构与公共事实对齐，语言自然，不逐句硬译。

- 适合做什么：真实能力及开始前必须知道的限制。
- 环境准备：使用推荐路径真正需要的条件。能合理提供获取方式时链接官方入口；闭源软件说明用户应具备的兼容版本和可用条件，不猜测安装流程。关键范围不明再问。
- 快速开始：先推荐一条最合适的实际可用路径，有必要才分支。发行版、插件市场、npm/npx 或源码由当前项目决定，不能把计划中的方式写成已可用。
- 接下来怎么用：说明常用下一步，按需链接使用说明；只有确实需要修改文件时才告诉用户改什么。
- 常见问题：只保留首次使用的常见阻碍，日常问题进入使用说明。
- 更多文档：用户用法与项目进展入口。
- 参与贡献：邀请用户提出尚未覆盖的需要，共同维护、提交代码或文档；链接真实贡献入口和开发者技术资料。不默认创建完整 CONTRIBUTING。

开发依赖的用途、关系和必要版本在技术文档说明，不在 README 增加开发环境安装教程。README 不成为所有知识的副本。
