# 额度恢复后自动续跑

为指定的未完成任务建立可恢复、可停用的续跑机制。面向五小时额度窗口，同时检查周额度等适用限制，以实际额度状态决定是否续跑；五小时不是每次固定等待的时长。本技能只在用户显式调用时使用。

## 明确任务与调度路径

1. 确认目标任务身份、所属主机与账户、工作目录、剩余目标、完成证据，以及用户授权自动继续的范围。优先读取目标任务的当前状态，避免把已经完成或被用户停止的任务重新启动。调用本技能本身不等于授权创建定时任务；如果用户已明确要求创建并自动继续，则直接在该范围内执行，不重复确认。
2. 查找目标任务已有的调度和状态记录，优先修复或更新现有机制。一个目标任务只能有一个负责投递续跑消息的调度器。
3. 当前环境有适用的内置自动化工具时，优先使用它，并遵守该工具的调度、消息授权与目标线程契约。仅当用户明确选用本机调度，或没有适用工具时，才创建本机机制。不要为了绕过工具限制另建调度器。
4. 使用 Codex 作为执行端时，读取 [Codex 执行适配](references/codex-execution.md)；采用 Linux 本机调度时，再读取 [Linux systemd 调度](references/linux-systemd.md)。当前配套资料只覆盖这两个适配，不推断其他客户端的额度接口或其他操作系统的调度方法。本插件带有可复用的参数化控制器（[`scripts/quota_resume.py`](scripts/quota_resume.py)，用法见 [`references/controller-usage.md`](references/controller-usage.md)）：优先适配它，新增任务一般只需任务配置与续跑指令，不必重新生成调度器。

## 设计续跑契约

先确定状态转换、额度检查、执行回执和停止规则，再生成对应实现。等待额度、查询额度、回执跟踪及已授权的卡兑换必须由无需新模型推理的调度层完成，避免额度耗尽后还需启动模型才能恢复。评估内置自动化是否具备这些能力，不能仅因存在 heartbeat 就宣称满足恢复契约；不具备时说明限制，并在用户已授权的本机调度路径实施，缺少相应授权则先交付限制与可审阅方案，不扩展外部动作。

| 状态 | 后续动作 |
| --- | --- |
| `waiting_quota` | 到额度重置时间后重新查询；没有可信重置时间时，按有限退避复查 |
| `queued` | 核对消费职责，必要时启动同一条排队消息；在约定期限内追踪，不重复入队 |
| `running` | 跟踪对应执行轮次及既有机制处理的自动审批等待，不追加续跑消息 |
| `retry_wait` | 在截止时间内按有限退避恢复网络或服务查询 |
| `completed` | 已有任务完成证据，持久记录后停用调度 |
| `needs_attention` | 保存确需人工审批或输入、审批被拒绝或等待超时等阻塞原因，停止自动续跑 |
| `stopped` | 保留用户停止记录；进程或机器重启不自动清除 |

- 区分普通订阅额度与其他计费路径；不得自动切换账户、模型计费方式或付费额度。额度允许执行只是续跑的必要条件，仍须处理提交后才出现的额度错误。
- 创建时记录额度恢复方式：默认等待自然恢复；仅在用户明确授权的账户、任务、次数上限与适用限制内兑换已有重置卡。支持卡的能力不等于本次消费授权，兑换已有卡也不等于授权购买。已有明确授权不重复询问，缺项只澄清缺项；无人值守时没有完整授权就继续等待。
- 把重置时间用于安排下一次检查，不能用它、剩余百分比或经过五小时推断额度已经恢复。缺失或未知额度值保持未知，不当成有额度或无额度。
- 打开的会话可能仍持有写入权，却没有模型在运行。有持有者时复用其宿主路由；确认没有持有者时，按平台支持的方式加载原任务并保留既有权限。归属不明时有限核对，不能把占有写入权一律当作忙碌并无限等待。
- 保存任务、续跑尝试、消息与执行轮次的关联。持久去重覆盖调度重启和提交中断；进程锁只能避免控制器并发，不能替代去重。
- 入队回执只证明 `queued`。仅在匹配的轮次被执行后记录 `running`；轮次正常结束也不必然代表整个任务完成，须核对事先约定的完成证据。
- 一轮结束后，若剩余工作在授权范围内可执行且额度允许，则继续下一次尝试；按事先定义的次数或时长限制检测无进展循环，达到限制后保存原因并停止报告。
- 对网络失败使用有限次数、有限总时长的退避；对额度不足等待恢复后复查。人工停止进入 `stopped`；确需人工审批或输入、审批被拒绝或等待超时进入 `needs_attention`。由既有机制处理的自动审批在期限内继续跟踪，不自行批准、改变审批策略或用“继续”消息越过。
- 固定续跑指令必须保留原任务范围、当前进度、完成条件与停止规则。自动续跑不扩展提交、推送、发布或重复外部动作的授权；不确定动作是否已发生时先核对结果。

## 实施与交付

1. 保存旧配置和状态的备份，生成可审阅的调度配置、控制器和停止方式。实际路径从当前目标环境解析，不照搬样例中的个人路径或其他任务的线程 ID；凭据沿用私有配置，不写进生成物。先核对当前运行环境的实际接口，再实现适配。
2. 启用前检查目标、时间、环境、状态持久化与停止规则；创建新机制时保留已有任务的终态，不以初始化覆盖它。续跑指令应要求完成后提供可核对证据，控制器据此确认完成并停用调度。
3. 在已授权范围内使用有限真实续跑核对回执：自动触发 → 消息被消费 → 匹配轮次执行 → 结果可确认 → 按规则继续等待或停止。不要为验收额外创建会话、任务或模型调用；如没有适合验证的未完成任务，交付静态检查结果并明确真实续跑尚未验证。
4. 汇报配置位置、目标任务、下一次检查时间及其时区、额度判定依据、启停与回滚方法、已观察到的执行状态。把“配置通过”“已入队”“已执行”“任务完成”分开报告；服务退出码为零或命中锁保护不能算续跑成功。

默认只在状态有意义地改变、任务完成、发生失败或需要用户处理时通知，等待期间不重复发送无变化的消息。
