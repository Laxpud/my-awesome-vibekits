# Linux systemd 调度

仅在用户明确选用 Linux 本机调度，或没有适用内置自动化工具时读取并实施。这里定义控制器的运行契约。

本插件已带一个可运行、可复用的参数化实现，位于 [`../scripts/quota_resume.py`](../scripts/quota_resume.py)：
新增任务通常只需写一份任务配置与一份续跑指令，**不需要重新生成调度器**。
先按 [`controller-usage.md`](controller-usage.md) 核对该实现的接口；
只有在目标环境与其不兼容时，才依据下述契约生成新实现。本文件不提供可直接安装的通用脚本。

## 配置与状态

使用用户级 service/timer，不需要系统级安装。为任务选择稳定且不冲突的单元名，将配置放在用户 systemd 配置目录，将控制器状态与日志放在用户状态目录；通过实际环境解析路径，不硬编码用户名。一个任务一个状态目录，限制为当前用户可访问，避免记录凭据和完整敏感提示。

控制器状态至少覆盖以下含义，字段名可根据实现调整：

| 内容 | 用途 |
| --- | --- |
| 状态格式版本、目标线程 ID、所属主机与账户、宿主选择方式与路由、工作目录 | 防止旧状态被误用于新任务；区分复用持有者与受控加载原线程 |
| 当前状态、状态修改时间 | 恢复调度决策，保留终态 |
| 尝试 ID、客户端关联 ID、服务端消息 ID、轮次 ID | 跨进程追踪提交、消费与执行 |
| 下一次检查时间、重试次数、重试截止时间 | 避免无界循环或立即重试 |
| 队列消费方式、启动意图与回执、消费期限；审批接收方与等待期限 | 恢复同一消息的启动追踪，区分自动审批与人工阻塞 |
| 最近额度结果、失败类别与原因 | 区分等待、未知与需要人工处理 |
| 五小时与周窗口、适用模型额度桶 | 按实际限制安排复查，避免误用其他周期或模型的结果 |
| 重置卡授权、次数上限与预留、兑换意图及幂等键、结果 | 防止重启或回执丢失导致越权、超限或重复兑换 |
| 连续无进展次数与截止时间 | 防止正常结束但没有推进的轮次无限循环 |
| 任务完成证据或停止原因 | 支持审阅与自动停用 |

状态文件采用同目录临时文件写入再原子替换，并按恢复要求保证落盘。取得进程锁后再读取和修改状态；锁退出记录 `skipped_busy`，不记作投递成功。终态必须持久保留，重启服务或重载单元不得重置。

## 定时策略

可采用短周期轻量唤醒：例如每分钟启动控制器，先读取本地 `next_check_at`，未到时间立即退出，不查询额度、不调用模型。到期后才执行必要的查询。也可依据实际环境使用一次性调度，但要覆盖重启恢复、时间变动及遗漏触发。

不要使用 `OnUnitInactiveSec=5h` 表达额度恢复或模型工作结束后的五小时：它从 service 退出计算，通常只反映控制器运行时间。重置时间由后端提供时，在其之后留少量可配置余量再查；无可信重置时间时有限退避，并明确当前依据是回退策略。排队和执行期间按适度间隔查询回执，不追加消息。

机器休眠或关机期间不能保证执行。说明机器醒来后的恢复行为；如果用户需要退出登录后仍运行，先检查用户服务管理器和现有 linger 状态，仅在该需求及授权范围内调整，不默认修改系统策略。

## 服务运行环境

- 使用已解析的可执行文件绝对路径，明确工作目录；systemd 不继承交互式 shell 的完整环境。
- 对网络、代理、认证和 D-Bus 等实际依赖逐项核对；凭据通过现有私有配置提供，不写入单元、仓库或日志。
- 定时控制器应落实已选执行路径：存在持有者时访问其宿主路由；确认没有持有者时，按受支持的方式加载原线程，并保证受控宿主能在两次检查之间继续执行和提供回执。路由失效不等于没有持有者，应重新发现并有限恢复；加载时遇到写入冲突则回到持有者路径，不争抢或删除锁。
- 每次控制器运行应有超时；长任务通过持久回执跟踪，不让单次 service 无限等待。网络重试和服务重启策略需与控制器退避协调，避免两层无限重试。
- 配置修改后执行 `systemd-analyze --user verify`、`systemctl --user daemon-reload`，再按已授权范围启用。核对 timer 下一次唤醒与控制器的下一次有效检查时间，两者可能不同。

## 观测、停止与回滚

日志使用独立事件记录 `waiting_quota`、`queued`、`running`、`completed`、`retry_wait`、`needs_attention` 和 `skipped_busy`，包含时间、任务与尝试关联以及可诊断原因。不要仅凭 `systemctl` 的成功退出状态统计续跑成功。

用户停止时，先持久记录 `stopped`，再停用 timer；已有执行轮次按用户意图处理，不把停止定时器等同于取消已提交消息。完成或需要人工处理时，控制器先持久记录终态再停用 timer。终态还应使误触发的 service 安全退出。

交付具体的 `systemctl --user` 查询、停用和恢复命令及配置位置。恢复需要显式处理终态并重新核对目标，不以删除状态文件作为常规重试方法。回滚时停用新调度，恢复备份并重载单元；保留本次回执日志，说明旧配置恢复后是否仍保持停用。
