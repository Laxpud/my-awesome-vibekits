# ADR：少量长期重要决定

默认 `docs/adr/0001-short-title.md`。不再创建职责相同的 decisions 目录，也不因 milestone、plan 或 spec 存在就创建 ADR。

除用户明确要求外，只有以下三项同时成立才值得保存：

- 决定难以或代价高昂地撤销。
- 后续读者不知道背景会难以理解该选择。
- 存在真实取舍，而不是常规实现细节或唯一可行路径。

## 最小模板

```markdown
# 0001：采用独立后端接口

状态：已接受

决定：让各后端实现同一个导出接口。
原因：两个后端输入相同但运行环境不同，统一接口可以保持调用方稳定。
代价：后端特有能力需通过单独扩展表达。
```

正文通常一至三句足够；状态、后果与相关链接仅在有用时补充。示例不能替代真实取舍。不要求列出虚构备选方案或把 plan/spec 重新提炼一遍。

已接受 ADR 不改写成新的历史。决定变化时新增 ADR，旧条目标为被替代并互链；纠正笔误或链接不改变原意。ADR 是长期记录，不随里程碑归档。重命名、移动或替代时检查受影响链接，不为普通任务重复检查所有 ADR。
